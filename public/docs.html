DLL Store API

Upload and retrieve binary files (e.g. .dll) backed by SQLite. All bytes are stored as a BLOB column.

Overview

Base URL when running locally: http://localhost:3000

Every stored file gets a numeric id, a SHA-256 hash, size, filename, and upload timestamp. File bytes are only returned by the single-file GET endpoint — the list endpoint returns metadata only.

Endpoints

POST /api/files
Upload a file. Two supported formats:

1. multipart/form-data — field name must be file

curl -X POST http://localhost:3000/api/files \
  -F "file=@mylib.dll"

2. Raw binary — set Content-Type: application/octet-stream and pass the filename as a query param

curl -X POST "http://localhost:3000/api/files?filename=mylib.dll" \
  -H "Content-Type: application/octet-stream" \
  --data-binary @mylib.dll

Response 201:

{
  "id": 1,
  "filename": "mylib.dll",
  "size_bytes": 48640,
  "sha256": "c3ab8ff1...",
  "uploaded_at": "2026-07-27 10:00:00"
}
GET /api/files
List metadata for all stored files (no bytes returned).
curl http://localhost:3000/api/files
[
  {
    "id": 1,
    "filename": "mylib.dll",
    "size_bytes": 48640,
    "sha256": "c3ab8ff1...",
    "uploaded_at": "2026-07-27 10:00:00"
  }
]
GET /api/files/:id
Download the raw bytes of a stored file. Returns application/x-msdownload with a Content-Disposition attachment header.
curl -OJ http://localhost:3000/api/files/1
GET /api/files/:id/meta
Return metadata only (no bytes) for a single file.
curl http://localhost:3000/api/files/1/meta
DELETE /api/files/:id
Delete a stored file by id. Returns 204 No Content on success.
curl -X DELETE http://localhost:3000/api/files/1

Database schema

ColumnTypeNotes
idINTEGERPrimary key, autoincrement
filenameTEXTOriginal filename as uploaded
size_bytesINTEGERFile size in bytes
sha256TEXTHash of the file content, for integrity checks
contentBLOBThe raw file bytes
uploaded_atTEXTUTC timestamp, set automatically

Limits & notes

Max upload size is 200 MB by default (configurable via MAX_FILE_BYTES in server.js). The database file lives at dll_store.db next to the server, or wherever DB_PATH points.
